## 输入、数据和调用关系

|拟脚本|读取|写出/调用|审阅及停止点|
|---|---|---|---|
|inspect-input|用户指定路径/原片|source-manifest、工作副本映射；已有媒体元数据能力/FFmpeg|确认旋转、音画起始PTS、音轨、VFR；当前ffprobe历史有架构不兼容，不能默认调用该坏路径|
|转录入口|已获准的同时间基准音轨|已有Whisper wrapper写独立transcripts目录；登记原TXT/SRT/JSON/日志|音频提取的0点不自动等于视频0点；保留映射。16kHz单声道仅用于识别，不替换最终原声|
|propose-cuts|原转录、take-log|候选JSON：原因、证据、保留/删除/换take、风险|Codex写候选；缺完整听看就不批准切点，不从粗段均分造词时间|
|validate-plan|批准计划、输入指纹、时间映射|计划诊断和FFmpeg参数数组/滤镜文本|缺阶段授权、原片SHA不匹配、未审、越界/重叠/跨词、时间基准未验时拒绝执行|
|execute-cut|批准保留区间、working副本|FFmpeg同时trim/atrim、时间归零、concat→base-cut|不改input；新输出名；同一源时钟裁音画，不只剪声音|
|remap-captions|同一批准区间、校对字幕|time-map、剪后Caption/ASS/SRT|字幕跨删段或take替换需人工重断句/核对，不静默截断含义；坏时间不是可用词对齐|
|compose-graphics|最终shot表/time-map、自有素材清单|graphics.timeline、渲染props|只用已审数据/素材；无来源数字/缺字体/越界/遮脸风险列出|
|render-review|基础片、props、组件或ASS方案|已有FFmpeg或未来已装/锁定的本地动画CLI→新review.mp4|不得自动安装缺失框架、下载模型或取远程私有素材；写日志、留失败输出|
|check-output|日志/成品元数据/审阅记录|qa.json|程序检查文件、时长、缺素材；本人完整听看管裁字/语气/衔接/同步。任一失败保留PENDING/FAIL|

stage_permission和human_cut_review是两层：前者是获准制作具体片；后者是剪哪些内容的实际确认。不能由Codex替用户把所有approved改成true。当段落或输入变化，相关计划作废；普通后续修正按已授权范围推进，不另增无依据的设计批准。

## 两个时间轴

原片说完一句可能在12秒；删完前面2秒后它应在10秒出现。字幕、图卡、录屏都依**最终成片时间**放置。`sourceIn/sourceOut`为工作副本的秒，`outputIn/outputOut`为拼接后秒，区间采用左闭右开。

虚构例：20秒、已经统一到30fps的working视频，保留[1.2,9.2)和[11.2,19.2)，得到16秒/480帧。原字幕[5.3,6.6)映射[4.1,5.4)，原字幕[12.2,13.7)映射[9.0,10.5)。转换公式：

```text
outputTime = outputInOfClip + (sourceTime - sourceInOfClip)
```

这是数学示例，不是对真实说话或切点的精度证据。数据文件显式synthetic=true、DRAFT、approved=false、输入SHA为空、原片映射verified=false。即使算术一致，仍不得执行。

16秒数学例专门说明时间映射，不是82秒拍摄表的完整时间线；82秒台词尚未拍摄，源时间未知，不能提前编造真实cut-plan。

帧时间只在已统一/核实的工作文件时钟下转换；VFR原片、原音轨偏移和转录音频0点未核时停止。以已审剪点取整/处理边界，不把毫秒变frame当作语音对齐。示例字幕是整句，不把粗SRT伪装成逐词高亮数据。

虚构16秒保留例的基础裁剪滤镜可以由execute-cut写成下面文本，再以参数数组调用已装FFmpeg（本轮未执行）。`-n`拒绝覆盖，input指向工作副本而非原片。

```bash
ffmpeg -n -i derived/working-cfr.mp4 -filter_complex \
"[0:v]split=2[vx0][vx1];[0:a]asplit=2[ax0][ax1];
 [vx0]trim=start=1.2:end=9.2,setpts=PTS-STARTPTS[v0];
 [ax0]atrim=start=1.2:end=9.2,asetpts=PTS-STARTPTS[a0];
 [vx1]trim=start=11.2:end=19.2,setpts=PTS-STARTPTS[v1];
 [ax1]atrim=start=11.2:end=19.2,asetpts=PTS-STARTPTS[a1];
 [v0][a0][v1][a1]concat=n=2:v=1:a=1[v][a]" \
 -map "[v]" -map "[a]" -c:v libx264 -c:a aac derived/base-cut-v001.mp4
```

实际实施还需核编码参数、时间基准、中文字体、播放兼容和声画偏移，不能把这条例命令当已测成品配方。静音检测只写候选，禁止直接用silenceremove作为无人审阅删语义动作。[官方滤镜](https://ffmpeg.org/ffmpeg-filters.html)支持裁剪/归零/同步拼接，本例组织方法是本研究设计。

## 动画程序例：一张卡怎样加入真人片

下例为**自写、未编译、未执行**的结构说明，不复制博主私有模板。背景是已经剪好的16秒基础片；图卡在成片8—10秒出现。组件版式/数值只是设计例，无视觉验收。

```tsx
// 未执行。未来须锁定一致的Remotion包版本并核API。
const TalkLayout = ({baseCut, graphics}) => (
  <AbsoluteFill>
    <OffthreadVideo src={staticFile(baseCut)} />
    {graphics.map(card => (
      <Sequence key={card.id} from={card.fromFrame}
        durationInFrames={card.durationInFrames}>
        <StepCard text={card.text} />
      </Sequence>
    ))}
    <CaptionLayer captions={outputCaptions} />
  </AbsoluteFill>
);
```

StepCard可以用useCurrentFrame计算前6帧的opacity/translateY，再稳定显示；离场也按frame，不用不确定的墙钟计时。字幕已重映射；CaptionLayer需实现且核字号/换行。录屏作为单独Sequence插画面时静音，主原声音轨连续。素材缺失会报错，不悄悄用生成UI替代。

官方当前新视频使用建议是`@remotion/media`的Video；本例借OffthreadVideo解释已有契约，实际选库须读对应版本。若使用其durationInFrames新参数，文档标4.0.530；旧trimAfter/startFrom已弃用，不能照搬不锁版本的老教程。[组件](https://www.remotion.dev/docs/offthreadvideo)、[字幕](https://www.remotion.dev/docs/captions/displaying)为能力依据；代码例与布局未验证。

## 蓝图自检与实施验收分开

本轮可核：例JSON能解析、范围和整数帧计算自洽、两句字幕映射符合公式、全部标DRAFT/未批准、目标读写范围清楚。不能核：中文词对齐、实际剪点、真实音画/语气、字体和动画质量、耗时、输出兼容或收益。后续验证条件见工作流研究的“最小验证”，工程蓝图通过不等于试剪通过。
